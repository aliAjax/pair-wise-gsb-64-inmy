# 食品工厂HACCP控制计划与偏差处置平台

独立React前端工程，采用Fluent UI、Redux Toolkit、RTK Query、React Router、Vite和TypeScript。数据通过浏览器持久化，无需后端。

## 功能

- 生产批次、放行状态、监测点与隔离范围。
- HACCP流程图和控制矩阵编辑，记录关键限值、频率和纠偏措施。
- 偏差登记、原因与证据调查、返工/报废分支、复核退回和签字。
- 未关闭偏差阻止批次放行。
- 完整版本化审计和JSON追溯包导出。

## 原料召回行动中心（/recall）

从供应商通知出发，建立「原料批次 → 纸质领料单 → 生产批次 → 包装时段 → 成品去向」正向追溯：

- **通知唯一受理**：同一供应商召回通知号只立案一次，重复提交被拦截并审计。
- **命中即冻结**：立案后立即计算范围，命中生产批次、包装时段冻结放行，召回原料批次冻结仓库后续领用，已流向在途/门店/库存的成品同步冻结；生产批次页可见召回冻结标记且无法提交放行。
- **不得误判无影响**：旧领料单缺失原料批次的节点为「待补链」，包装时段无成品流向记录的为「待核查」，均挂出召回偏差，补齐前不会被当作无影响。
- **旧数据回填**：按纸质领料单回填原料批次后重算范围并发布新版本；证实无关的批次移出范围、解除冻结并关闭缺链偏差；回填命中召回批次则领用同步冻结。
- **统一召回版本**：每次范围变化升版并发布快照；批次范围、召回偏差、审计事件始终显示同一召回版本号。
- **两班长并行处置**：乐观版本锁。两班长可基于同一版本同时提交；范围先行变化时后提交者的确认标记为「失效保留」，页面展示具体范围变化（新增/移出/状态变更），原记录不删除，可按新版本重新确认。同一班长的有效确认不重复生成。
- **写入失败与恢复**：处置动作以动作键入账（幂等）。注入故障后动作生成在中途失败，已完成动作保留在账本，未完成动作保留在运行的 pendingKeys；恢复只续跑剩余批次，已确认结果绝不重复。
- 演练控制：注入写入故障、重跑动作生成、恢复未完成批次、模拟冻结后再次领料被拦截。
- 追溯审计页合并HACCP与召回事件，按召回版本号口径导出追溯包。

追溯引擎为纯函数（`src/recall/engine.ts`），行为测试覆盖8类场景：

```bash
npm install
npm run build
npm run test:recall
npm run dev
```

端口为`18464`。
